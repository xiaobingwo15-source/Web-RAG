# Fix: AI_Report.pdf Retrieval Failure

## Problem

User asks "what is the AI report talking about?" and the system responds: "I know the file exists but I don't have a summary of its actual content." The document has 64 chunks in Supabase and status=processed, but retrieval returns 0 chunks every time.

## Root Cause Analysis (3 interconnected issues)

### 1. Quality Score Overwrites Document Metadata (BUG — Primary Cause)

**File:** `backend/app/services/file_search_store.py`, line 328

```python
# Line 166-168: Stores {title, summary, tags, language, ...parser_metadata}
metadata = await extract_metadata(gemini_client, text[:2000])
metadata = {**metadata, **extraction.metadata}
update_document_metadata(access_token, document_id, metadata)

# Line 327-328: REPLACES entire metadata with only quality_score
metadata["quality_score"] = quality_score
update_document_metadata(access_token, document_id, {"quality_score": quality_score})
```

The second `update_document_metadata` call passes `{"quality_score": 0.8}` which **replaces** the entire JSONB column, wiping out the title, summary, tags, and language that were stored by the first call. Supabase `.update()` on JSONB does a full replace, not a merge.

**Evidence:** AI_Report.pdf metadata is `{"quality_score": 0.8}` while older documents (Chapter 1.pdf, uploaded before this code path existed) have full metadata including title, summary, tags.

### 2. FTS AND Semantics Prevent Content Matching

`plainto_tsquery('english', 'what is the ai report talking with')` generates `'ai' & 'report' & 'talk'`. FTS requires ALL terms to match. The document content is about "SupportLens: Customer Support Ticket Classification" — it contains 'ai' but NOT 'report' (appears in only 2 of 64 chunks as heading text) and NOT 'talk'. Result: 0 FTS matches.

### 3. Vector Search Semantic Mismatch

The query asks about "AI report" but the content is about "customer support ticket classification". Cosine similarity between query embedding and content embeddings is below the 0.1 threshold. Result: 0 vector matches.

## Fix Plan

### Fix 1: Preserve Metadata During Quality Score Update (Critical)

**File:** `backend/app/services/file_search_store.py`, line 328

**Change:** Pass the full `metadata` dict (which already includes quality_score from line 327) instead of just `{"quality_score": quality_score}`.

```python
# Before (line 328):
update_document_metadata(access_token, document_id, {"quality_score": quality_score})

# After:
update_document_metadata(access_token, document_id, metadata)
```

This ensures the quality_score is added to the existing metadata (title, summary, tags, language, parser metadata) without overwriting them.

### Fix 2: Add Filename-Based Retrieval Fallback (Important)

**File:** `backend/app/services/agents/doc_rag_agent.py`

When standard retrieval returns 0 chunks AND the user's query mentions a filename pattern (e.g., "ai report", "assignment brief"), add a fallback that:
1. Searches documents by filename using fuzzy/ILIKE matching
2. If a matching document is found, retrieves its chunks directly (bypassing vector/FTS search)
3. Uses those chunks as context for the answer

**Implementation:**
- Add `_try_filename_retrieval()` function after the early-exit at line ~1156
- Use `get_user_document_summaries()` to find documents whose filename matches the query
- If found, fetch chunks via `get_document_chunks()` and use them as context
- This handles the case where users ask about documents by name rather than by content

### Fix 3: Improve Clarification Response for Sparse Metadata (Nice-to-have)

**File:** `backend/app/services/agents/doc_rag_agent.py`, `_generate_clarification()`

When a document has no summary/tags but has a filename, generate a basic description from the filename:
- "The file 'AI_Report.pdf' exists in the knowledge base but I don't have a detailed summary. Would you like me to retrieve its content?"

**File:** `backend/app/services/database.py`, `get_user_document_summaries()`

When `summary` is empty, use the first 200 chars of the first chunk's content as a fallback summary.

### Fix 4: Re-process AI_Report.pdf Metadata (Data Fix)

After Fix 1 is deployed, re-process the AI_Report.pdf document to populate its metadata:
- Option A: Manually update the metadata via Supabase MCP
- Option B: Add an admin endpoint to re-run metadata extraction on existing documents
